# M3-T02 — Ruleset inheritance resolver

> Template. Every task gets a card like this before implementation begins.

## Goal

Resolve a ruleset id through its `extends` chain into one flattened `Ruleset`.

## Files you may create or modify

- `src/npc_planner/rules/ruleset.py`
- `tests/unit/test_ruleset_resolve.py`

## Files you may read but NOT modify

- `src/npc_planner/db/models.py`
- `data/rulesets/*.yml`

## Files you may NOT touch

Everything else. Verify with `git diff --name-only` before committing.

## Contract

```python
def resolve(ruleset_id: str, *, registry: RulesetRegistry) -> Ruleset:
    """Flatten the `extends` chain into a single Ruleset.

    Scalar keys: child overrides parent.
    List keys (bans, clauses): child CONCATENATES with parent,
        unless the child sets `replace_<key>: true`.
    Dict keys: shallow merge, child wins per key.

    Raises CircularExtendsError naming the cycle.
    Raises UnknownRulesetError naming the missing id.
    """
```

Resolution must be **pure and order-independent**: calling `resolve` twice
returns equal objects, and iteration order of any set or dict must not affect
the result. Sort before returning any list.

## Must-pass tests

1. `vanilla_gen3` resolves to itself; no parent lookup occurs.
2. `gba_modernized_no_items` resolves through 2 levels and inherits
   `damage_class_model == "split"` from the middle layer.
3. A child ban list concatenates with the parent's, deduplicated and sorted.
4. `replace_bans: true` discards the parent's ban list entirely.
5. A 3-node cycle raises `CircularExtendsError` naming all 3 ids.
6. An unknown parent id raises `UnknownRulesetError` naming the missing id.
7. `resolve(x) == resolve(x)` for all three shipped rulesets.

## Out of scope — do NOT implement
