## What to build

### `RomConfig`

```python
@dataclass(frozen=True)
class UnevaluatedExpr:
    symbol: str
    source_file: str
    raw: str
    reason: str

@dataclass(frozen=True)
class RomConfig:
    battle: Mapping[str, int | str]      # B_* from include/config/battle.h
    species: Mapping[str, int | str]     # P_GEN_N_POKEMON etc.
    pokemon: Mapping[str, int | str]     # include/config/pokemon.h
    limits: Mapping[str, int]            # PARTY_SIZE, MAX_MON_MOVES, ...
    ai_flags: Mapping[str, int]          # AI_FLAG_*
    difficulties: Mapping[str, int]      # DIFFICULTY_*
    unevaluated: tuple[UnevaluatedExpr, ...]
```

All mappings sort deterministically. `unevaluated` is ordered by
`(source_file, symbol)`.

### Functions

```python
def read_rom_config(layout: RomLayout) -> RomConfig: ...
def evaluate_int_expr(raw: str, known: Mapping[str, int]) -> int | None: ...
def physical_special_split_enabled(config: RomConfig) -> bool: ...
def enabled_generations(config: RomConfig) -> frozenset[int]: ...
```

`evaluate_int_expr` must support, without `eval`:

- decimal and hex literals
- `(1 << N)`
- `|`, `+`, `-`, and parentheses
- references to already-known symbols, resolved iteratively so
  `AI_FLAG_BASIC_TRAINER` and `DIFFICULTY_DEFAULT` resolve
- `TRUE` and `FALSE` only when the ROM tree defines them; otherwise they are
  ordinary unknown symbols

It returns `None` for anything it cannot evaluate. It never raises, never
guesses, and never returns `0` as a stand-in for failure. A `None` becomes an
`UnevaluatedExpr` with `reason` naming what stopped it.

**No `eval`, `exec`, `ast.literal_eval`, or `compile`.** Acceptance greps for
all four. A ROM tree is untrusted input and this reader will one day be pointed
at a stranger's fork.

Reuse `cparse.parse_defines` from M1-T09 for tokenising. If it cannot carry the
shift-expression cases, extend it there rather than writing a second parser in
`rom_config.py`; say so in the report.

### Behaviour on a missing header

A missing `include/constants/difficulty.h` is normal on older expansion
versions. Missing optional headers produce an empty mapping and no error. A
missing `include/config/battle.h` is fatal: raise `RomConfigError` naming the
path. `probe_layout` already distinguishes required from optional — do not
duplicate that judgement here.

## Must-pass tests

Preserve this section verbatim. `tests/unit/test_rom_config.py` unless noted.

1. `read_rom_config` on `fake_rom` returns `limits["PARTY_SIZE"] == 6`.
2. `limits["MAX_MON_MOVES"] == 4`.
3. `limits["NUM_STORAGE_BOXES"] == 14`, proving hex literals are read.
4. `limits["MAX_TRAINER_ITEMS"] == 4` from `constants/battle.h`.
5. `ai_flags["AI_FLAG_CHECK_BAD_MOVE"] == 1`.
6. `ai_flags["AI_FLAG_SMART_SWITCHING"] == 8192`, proving `(1 << 13)` is
   evaluated and not truncated.
7. `ai_flags["AI_FLAG_BASIC_TRAINER"] == 7`, proving symbol references resolve.
8. `difficulties["DIFFICULTY_DEFAULT"] == 1`, proving a define whose value is
   another symbol resolves.
9. `AI_FLAG_RUNTIME_TUNED` appears in `config.unevaluated` with a non-empty
   `reason`, and does **not** appear in `ai_flags`. An unevaluable flag must
   never reach the mapping with any value, least of all `0`.
10. `evaluate_int_expr("(1 << 3) | 0x10", {})` returns `24`.
11. `evaluate_int_expr("SOME_UNKNOWN", {})` returns `None` and does not raise.
12. Property test: for every symbol in `ai_flags`, the value is a positive
    integer and a power of two, except the composite. Use Hypothesis only if it
    is already a dev dependency; otherwise a plain parametrised test.
13. Deleting `include/constants/difficulty.h` from a copied fixture yields
    `difficulties == {}` and no exception.
14. Deleting `include/config/battle.h` from a copied fixture raises
    `RomConfigError`, and the message contains the path.
15. `read_rom_config` is deterministic: two calls return equal objects, and
    `list(config.ai_flags)` is identically ordered across calls.
16. In `tests/unit/test_fake_rom_fixture.py`: every declared fixture path
    exists, and no undeclared file exists under `fake_rom/`.
17. `RomLayout.config_constants` contains the five new headers and
    `config_headers` does not.
