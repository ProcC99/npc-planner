received; the tests below are what you write. Its behaviour:

### 3. The preprocessed count becomes derivable

`M1-T08` accepts `len(man['preprocessed']) == 5`. `RomLayout` names eight cpp-able headers
(`species_info`, `moves_info`, `abilities`, `types_info`, `items`, `level_up_learnsets`,
`teachable_learnsets`, `egg_moves`); `wild_encounters_json` and `trainers` cannot be preprocessed.
Nobody can derive `5` from anything, which is how it survived unexamined.

Add to `src/npc_planner/ingest/rom_probe.py`:

```python
# RomLayout attributes that are C headers and therefore cpp-able.
# wild_encounters_json is JSON and trainers is a .party file; neither is preprocessed.
PREPROCESSABLE_FIELDS: tuple[str, ...] = (
    "species_info",
    "moves_info",
    "abilities",
    "types_info",
    "items",
    "level_up_learnsets",
    "teachable_learnsets",
    "egg_moves",
)
```

Do **not** change what `preprocess_rom.py` actually preprocesses in this task. Instead, discover
the truth and record it:

1. Run the existing preprocessor against `tests/fixtures/fake_rom` and count the emitted `.i`
   files.
2. If the count equals `len(PREPROCESSABLE_FIELDS)`, the literal `5` was simply wrong; assert the
   derived value everywhere and note the correction in the commit body.
3. If the count is lower, some fields resolve to the same file or to no file in this layout. Add
   `RomLayout.preprocessable_paths() -> list[Path]` returning the de-duplicated, existing paths
   for `PREPROCESSABLE_FIELDS`, and assert against `len(layout.preprocessable_paths())`.

Either way, **no test or acceptance script may contain a literal count after this task.** Every
assertion compares the manifest against a value derived from `RomLayout`.

## Must-pass tests

In `tests/unit/test_hooks.py`, using a temporary git repo built by the `git_fake_rom` pattern
(a fresh `git init` in `tmp_path`, isolated `GIT_CONFIG_GLOBAL`):

1. A commit message with no task tag returns 0 regardless of staged files.
2. A tagged message whose card is absent from HEAD returns 1, and stderr contains
   `not committed in HEAD`.
3. A tagged message whose card exists in HEAD and whose staged files all match returns 0.
4. Staging one file outside the allowlist returns 1, and stderr names that exact path.
5. `docs/LEDGER.md` is accepted even when absent from the card's list.
6. A glob pattern in the card (`tests/unit/test_*.py`) matches a staged file.
7. A trailing-slash directory pattern matches a file beneath it.
8. A card present in HEAD with an **empty** allowlist section returns 1 with
   `no parseable` in stderr.
9. **The allowlist is read from HEAD, not the working tree**: commit a card with a narrow list,
   then widen the list on disk without committing, stage a file allowed only by the widened list,
   and assert the hook still returns 1.
10. `PREPROCESSABLE_FIELDS` is a subset of `RomLayout`'s field names, and contains neither
    `wild_encounters_json` nor `trainers`.
11. The `ROM_MANIFEST.json` written for `tests/fixtures/fake_rom` has a `preprocessed` count
    equal to the value derived from `RomLayout`, with no literal in the assertion.
12. `bash -n` passes over every file in `scripts/accept/` - written as a loop over the directory,
    not a hardcoded file list, so future scripts are covered automatically.

Test 9 is the one that matters most. Without it the hook is trivially bypassed by editing the
card before committing, which is exactly the behaviour §11.1 exists to prevent.
