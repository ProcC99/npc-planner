# M1-T10b - Correct the ROM config reader and close the done-tag loophole

**Commit subject:** `fix(ingest): correct config reader bucketing and symbol coverage   [M1-T10b]`

## Why this task exists

`M1-T10` was merged with acceptance 32/32 green and a reader that silently drops
symbols. The evidence is in the T10 report itself:

```json
"pokemon": {
  "GUARD_CONFIG_BATTLE_H": "#define B_PHYSICAL_SPECIAL_SPLIT GEN_3",
  "GUARD_CONFIG_POKEMON_H": "#define P_HIDDEN_ABILITIES TRUE",
  "GUARD_CONFIG_SPECIES_ENABLED_H": "#define P_GEN_1_POKEMON TRUE"
}
```

A valueless `#define` (an include guard) consumed the following line as its
value. Four confirmed losses, none reported in `unevaluated`:

| Symbol | Should be in | Actual |
| --- | --- | --- |
| `B_PHYSICAL_SPECIAL_SPLIT` | `battle` | absent |
| `P_HIDDEN_ABILITIES` | `pokemon` | absent |
| `P_GEN_1_POKEMON` | `species` | absent |
| `DIFFICULTY_EASY` | `difficulties` | absent |
| `EXPANSION_VERSION_MAJOR` | `versions` | absent |

The two functions T10 existed to deliver are therefore both wrong on the
fixture: `physical_special_split_enabled` reads a key that is not there, and
`enabled_generations` omits generation 1.

Secondary defects: guard symbols were bucketed into `pokemon` regardless of
source file, and `limits` became a catch-all holding `B_SIDE_PLAYER` and
version numbers.

Separately, two commits landed under `[M1-T08e]` after T08e was recorded `done`
(`7d22d8f`, `737dc19`). A completed task's tag is a permanent skeleton key and
the auditor calls both clean. This task closes that.

## Part A - the parser

### A1. Valueless defines

`#define FOO` with no value is a **flag definition** with value `1`. It never
consumes the following line. This is the root cause and it is one rule.

### A2. Include guards are ignored, not parsed

A valueless define whose name starts with `GUARD_` or ends with `_H` is an
include guard. Record it in a new `RomConfig.ignored: tuple[str, ...]` and put
it in no bucket. Guards are the only thing that may be ignored; add a
module-level comment saying so.

### A3. Bucket by source file, not by accident

```python
BUCKET_BY_FILE: Mapping[str, str] = {
    "include/config/battle.h": "battle",
    "include/config/species_enabled.h": "species",
    "include/config/pokemon.h": "pokemon",
    "include/constants/battle_ai.h": "ai_flags",
    "include/constants/difficulty.h": "difficulties",
}
```

Everything else under `include/constants/` is split two ways:

```python
LIMIT_SYMBOLS: frozenset[str] = frozenset({
    "PARTY_SIZE", "MAX_MON_MOVES", "MAX_MON_MOVES_IN_BATTLE", "MAX_LEVEL",
    "MAX_BATTLERS_COUNT", "MAX_TRAINER_ITEMS", "NUM_STORAGE_BOXES",
    "POKEMON_NAME_LENGTH", "TRAINER_NAME_LENGTH", "ITEM_NAME_LENGTH",
})
VERSION_PREFIX = "EXPANSION_VERSION_"
```

- name in `LIMIT_SYMBOLS` goes to `limits`
- name starting with `VERSION_PREFIX` goes to a new `versions` mapping
- anything else goes to a new `constants` mapping

`limits` must contain nothing outside `LIMIT_SYMBOLS`. `B_SIDE_PLAYER` and
`B_SIDE_OPPONENT` belong in `constants`. Version numbers belong to the lockfile
`rom_source` block, and putting them in `limits` would have quietly widened
that contract.

### A4. Baseline symbol seeding, declared and pinned

`GEN_3`, `TRUE` and `FALSE` are not defined anywhere in the fixture, so they
must be seeded. Seeding is an assumption, so it is declared in exactly one
place and pinned by a test:

```python
BASELINE_SYMBOLS: Mapping[str, int] = {
    "FALSE": 0, "TRUE": 1,
    "GEN_1": 1, "GEN_2": 2, "GEN_3": 3, "GEN_4": 4, "GEN_5": 5,
    "GEN_6": 6, "GEN_7": 7, "GEN_8": 8, "GEN_9": 9,
}
```

If the real repo defines any of these differently, the repo wins. A test
asserts the mapping's exact contents so it cannot quietly grow into a place
where real ROM data gets guessed.

### A5. The two predicates must never default

```python
def physical_special_split_enabled(config: RomConfig) -> bool:
    """True when the hack uses per-move damage classes.

    Raises RomConfigError if B_PHYSICAL_SPECIAL_SPLIT is absent. There is no
    safe default: guessing here silently rewrites every damage calculation.
    """
```

Semantics: the value is a generation number. The split is enabled when that
number is 4 or greater. The fixture says `GEN_3`, so the fixture answer is
`False`.

`enabled_generations(config) -> frozenset[int]` returns every `N` where
`P_GEN_N_POKEMON` is truthy. Absent means absent, not disabled: if no
`P_GEN_*` key is present at all, raise `RomConfigError`.

### A6. Coverage - the check that generalises

This is the important one. Everything above fixes symptoms I can see in a
fixture I wrote. This catches the ones I cannot see in your actual repo.

```python
def audit_coverage(layout: RomLayout, config: RomConfig) -> tuple[str, ...]:
    """Return every symbol defined in a scanned header that is unaccounted for.

    A symbol is accounted for if it appears in exactly one bucket, or in
    config.unevaluated, or in config.ignored. Anything else has been lost.
    Returns a sorted tuple; empty means total coverage.
    """
```

Re-scan the headers independently of the parse - count every line whose first
non-whitespace token is `#define` - and diff against what the parse produced.
A symbol appearing in two buckets is also unaccounted for; report it.

Nothing is allowed to be dropped without being named. That is the whole
provenance model in one function, and its absence is why 32/32 passed on a
broken reader.

## Part B - the done-tag loophole

In `scripts/hooks/task_id_required.py`, after the tag is extracted, read
`docs/LEDGER.md` from `HEAD` and locate the row for that task id. If the row
shows status `done` **and** a non-empty sha, reject:

```
task M1-T08e is recorded done at ef6e0c6; its tag cannot authorise new work.
open a lettered follow-up card, or use [ci] / [ledger] / [protocol].
```

If the ledger cannot be read from `HEAD`, or the row is missing, allow the
commit - the hook must not become a second way to brick the first commit of a
task. Failing open here is deliberate.

Add `[ci]` to both `task_id_required.py` and `audit_commits.py`:

```python
SCOPE_TAG = re.compile(r"\\[(ledger|protocol|ci)\\]")
CI_SCOPE = (".pre-commit-config.yaml", "Makefile", ".github/")
```

and **remove** `.pre-commit-config.yaml` from `PROTOCOL_SCOPE`. Section 11.5
says narrow, do not weaken; folding CI machinery into `[protocol]` let a
documentation tag change which hooks run.

The auditor must now flag `7d22d8f` and `737dc19` as violations. Expected total
goes from 14 to **16**, and both are added to the Known Historical Violations
section of the ledger with a one-line note that they were tag-shopping, not
malice.
