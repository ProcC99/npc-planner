## What to build

### 1. `scripts/check_hooks_installed.py` — supplied

Install the file as delivered. It checks that `.git/hooks/pre-commit` and
`.git/hooks/commit-msg` exist and were written by pre-commit, honouring
`core.hooksPath`. Wire it as the **first** prerequisite of `make check`:

```make
check: hooks-check lint typecheck test-unit test-int schema-check

hooks-check:
	python3 scripts/check_hooks_installed.py
```

### 2. `scripts/audit_commits.py` — supplied

Install as delivered. It re-applies the tag and allowlist rules to commits that
already exist, reading each card from that commit's own tree.

### 3. Scope tags in `task_id_required.py`

Replace the current "subject must contain a task id" rule with "subject must
contain exactly one scope tag". The two patterns are the ones already used in
`audit_commits.py`; copy them from there so the hook and the audit cannot drift:
one matching a task id such as `M1-T08e`, one matching the literals `ledger` or
`protocol`, both requiring square brackets.

Exactly one must match. Zero matches is a rejection with a message naming the
three tags. Both matching is a rejection. Merge commits (a `MERGE_HEAD` file in
the git dir) are skipped.

### 4. Scope tags in `files_within_allowlist.py`

Add `LEDGER_SCOPE` and `PROTOCOL_SCOPE` exactly as defined in
`scripts/audit_commits.py`, and consult them before the card lookup. A
`[ledger]` or `[protocol]` commit is checked against its fixed scope instead of
a card.

Task-tagged behaviour, including reading the allowlist from `HEAD`, is
unchanged — do not weaken it (11.5).

### 5. `make gate`

Exactly as written in Correction G, including `ruff format --check` and `ruff
check` with **no** `--fix`. Fix whatever this newly surfaces; that backlog is
real and has been invisible for four tasks.

### 6. Apply Amendment 11 rev 3

Corrections D, E, F, G into `EXECUTION_PROTOCOL.md` as sections 11.7 (rewritten),
6 (amended), 11.9, 11.10 — all before Appendix A. Reduce
`docs/PROTOCOL_AMENDMENT_11.md` to the supplied stub.

## Must-pass tests

Preserve this section verbatim. Add to `tests/unit/test_hooks.py` unless noted.

1. An untagged commit message is **rejected** by `task_id_required`.
2. A subject carrying only a task tag is accepted by `task_id_required`.
3. A subject carrying only `[ledger]` is accepted by `task_id_required`.
4. A subject carrying only `[protocol]` is accepted by `task_id_required`.
5. A subject carrying both a task tag and `[ledger]` is rejected.
6. `fixup! update task_id_required to support task letter suffixes` — the exact
   M1-T08d subject — is rejected. This is the regression test for the loophole.
7. A `[ledger]` commit staging only `docs/LEDGER.md` is accepted by the allowlist hook.
8. A `[ledger]` commit also staging `src/foo.py` is rejected.
9. A `[protocol]` commit staging a card and `EXECUTION_PROTOCOL.md` is accepted.
10. A `[protocol]` commit staging `scripts/hooks/anything.py` is rejected.
11. Task-tag behaviour is unchanged: the HEAD-not-worktree test from M1-T08d
    still passes. Widening the allowlist in the working tree has no effect until
    committed.
12. `check_hooks_installed.py` exits 0 in a repo where pre-commit is installed.
13. `check_hooks_installed.py` exits 1, and names the missing stage, in a temp
    repo with an empty `.git/hooks`.
14. In `tests/unit/test_audit_commits.py`: build a throwaway repo with three
    commits — one clean task commit, one untagged, one task commit touching an
    off-allowlist file. `audit_commits.main` returns 1 and reports exactly the
    latter two.
15. `audit_commits.py` reads each card from the commit being audited, not from
    the tip. A commit whose card later gained a wider allowlist is still
    reported.
